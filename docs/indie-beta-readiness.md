# 꾹꾹 디펜스 · 첫 인디 베타 출품 게이트

기준 후보: 0.17.1. **현재 후보를 인디 베타 완료로 선언하지 않는다.** 아래 항목은 저장소 코드 검토와 기존 QA 범위를 구분하여 관리한다.

## 플레이 계약

- **시작:** 첫 방문자가 메인 버튼과 목표를 이해하고, 전투 없는 연습을 선택할 수도 있다.
- **핵심 루프:** 재질을 보고 누르거나 탭한다 → 부화 성공/실패가 즉시 구별된다 → 동료가 실제 전장에 합류한다 → 5무리와 마지막 보스를 막는다.
- **진행:** 현재 무리, 부화장 체력, 합류한 동료와 남은 적을 계속 파악할 수 있다. 복잡한 속성 시스템 설명은 선택적으로 제공한다.
- **종료:** 승리/패배의 결과가 분명하며 이번 기록·최고 기록·획득 조개를 구분한다. 성장 구매 후 새 도전을 시작할 수 있다.
- **회복:** 일시정지와 메뉴·입력 취소가 현재 상태를 보존한다. 진행 중인 방어를 포기하는 경우에만 확인을 받는다. 도감·조개·영구 성장은 재시작 후에도 유지한다.

## 0.17.1에서 변경한 범위

- 타이틀의 장황한 재질 소개를 첫 번째 유저 행동과 승리 조건 중심으로 바꾸었다.
- 전투 상단의 기술 구현 용어를 유저가 수행할 목표로 바꾸었다.
- 진행 중 방어 포기는 확인 후에만 초기화하며, Esc/돌아가기는 일시정지로 복귀한다. 연습 종료·이미 끝난 게임의 타이틀 복귀는 추가 확인하지 않는다.
- 결과의 상세 기록에 최고 무리, 누적 승리, 이번 획득 조개, 이번 실패를 표시한다.
- 모바일 및 낮은 가로 화면에서 게임 목표와 조작 안내의 작은 글자를 키웠다.
- 기존 브라우저 E2E의 방어 시나리오에서 확인 취소/복귀를 검사한다.
- HTML 표시 버전과 게임 내부 BUILD 버전이 0.15.1 / 0.17.0으로 달랐던 상태를 0.17.1로 맞췄다. 이 수정을 기존 Stable 검증으로 간주하지 않는다.

## 검증 순서

1. `npm run check` — 현재 소스·SDK·SVG 참조/구문을 확인한다.
2. `npm test` — 기존 실제 브라우저 부화/오디오/일시정지/방어 흐름과 방어 포기 확인을 본다.
3. `npm run test:growth` 및 `npm run test:mobile-pages` — 성장과 두 방향 레이아웃, 선택/복귀/결과 표시를 확인한다.
4. 실제 PC 및 모바일에서 사람의 무보조 한 판 플레이와 재도전을 기록한다. 이후에만 필요 범위를 좁혀 밸런스·첫 볼 가이드·피드백을 조정한다.

**릴리즈 판정:** 정적 CI PASS나 자동 클리어만으로 Validated/Stable 전환하지 않는다. 실제 플레이의 막힘/오입력/결과 회복 문제를 해소한 뒤 후보를 검증하고, 전시 사이트에는 그때 검증한 태그를 쓴다. 별도 대규모 게임 시스템, 10개 이상의 새 영구 테스트, 불필요한 배포 번들 구조는 만들지 않는다.
